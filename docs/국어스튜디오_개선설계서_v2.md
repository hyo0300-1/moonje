공통 원칙 (모든 기능에 적용)
1. **AI는 데이터만, 디자인은 렌더러가.** 결과는 JSON으로 저장하고 HWPX/PDF는 언제든 무료로 다시 렌더링.
2. **서버 작업 큐 하나 (`jobs`).** 브라우저 localStorage에 작업 상태를 두지 않음. 탭을 닫아도 계속 진행.
3. **견적 → 실행 → 실제 사용량 정산.** 모든 작업은 실행 전 무료 견적(dry-run)을 보여줌.
4. **기간 제한 없는 보관.** 지금의 "7일", "최근 1건", "최근 3건" 제한을 없앰.

## 1. 지문만 넣으면 주석이 달리는 기능 (주석 달기)

### 지금 확인된 방식
- 문제 출제의 "행간주" 카테고리 14개 프롬프트, 원클릭 자료의 앞자료 프롬프트 약 73개가 각각 따로 존재 (날개형, 노트형, 자습서형, 과외식, 빈칸형 …).
- 출력 계약은 `hanganju: analysis.sections[]` 에 **문장별 행간주를 문자열로** 넣는 방식. 주석이 지문 위치에 묶여 있지 않음.
- 디자인을 바꾸거나 필기량을 바꾸려면 **다른 프롬프트로 다시 생성(연필 재차감)** 해야 함.
- 행간주 프롬프트에는 미리보기가 없음.

### 개선 설계
**(1) 위치 고정형 주석 데이터 하나로 모든 디자인 출력**
- 지문을 `문단 > 문장 > 행` 세그먼트로 쪼개 ID를 붙이고, 주석은 `(시작 오프셋, 끝 오프셋, 인용문)` 으로 붙임.
- 같은 주석 데이터로 날개형 / 노트형 / 자습서형 / 과외식 / 빈칸형 / 교사용을 **렌더링만 바꿔** 출력. 73개 앞자료 프롬프트를 "레이아웃 6종 × 주석 데이터 1개"로 대체.
- 빈칸형은 주석 핵심어를 가리기만 하면 되므로 별도 생성 불필요.

**(2) 한 번 최대 밀도로 생성하고, 필기량은 렌더 단계에서 조절**
- 모든 주석에 `level 1~5` (중요도) 를 매겨 생성. 필기량 슬라이더는 `level <= n` 만 보여주는 필터.
- 필기량을 바꿔도 **추가 연필 0개**.

**(3) 2단계 생성: 규칙 기반 사전 주석 → AI 주석**
- 1단계 (무료, 즉시): 갈래 판별, 어휘 사전 매칭(고어·한자어), 표현법 탐지기(반복·대구·설의·영탄·도치·명령형 등 정규식 + 사전), 시어 반복 통계 → **결제 전 미리보기**로 바로 보여줌.
- 2단계 (AI): 1단계 결과를 힌트로 넣고 주석 카테고리별로 생성.
  - 카테고리: 어휘 / 현대어 풀이 / 표현법 / 화자·정서 / 인물·사건 / 구조 / 배경 / 문법 / 출제 포인트 / 기출 연계

**(4) 기출 연계 자동 표시**
- 문항 은행(EBSi 오답률 데이터, 저장한 시험지)에서 같은 문장이 근거로 쓰인 기출을 찾아 "★ 2025 9모 23번" 처럼 표시.
- 지금은 "08-99 기출된 문장 분석"이 별도 프롬프트인데, 이것을 모든 주석에 자동 적용.

**(5) 검증**
- 인용문이 원문에 없으면 지금은 조용히 버림 → **유사 매칭(정규화 후 편집거리 0.9 이상)으로 위치 복구**, 실패 시 "위치 확인 필요"로 표시해 교사가 클릭 한 번으로 연결.
- 겹치는 주석 충돌, 120자 초과, 같은 내용 중복 검사.
- 고전 어휘 뜻은 국립국어원 표준국어대사전 Open API로 대조.

**(6) 같은 작품 재사용**
- 지문 정규화 해시가 같으면 이전 주석을 불러오고 **바뀐 부분만** 생성 (교과서 수록 작품은 반복 사용이 많음).
- 교사가 고친 표현은 개인 스타일 메모리로 저장(선호 용어, 금지 표현)해서 다음 생성에 반영.

### 완료 기준
- 디자인 6종, 필기량 5단계 전환에 재생성 없음.
- 주석 위치 유실률 1% 미만 (지금은 유실 시 조용히 삭제).

## 2. 주석교재 만들기: 첨부자료로 필기량·스키마 정교화

### 지금 확인된 방식
- 입력: 제목, 작가, 갈래(자동/수동), 원문, 추가 요청, **학교 프린트·수업 자료 드롭 최대 5개** → 텍스트만 뽑아 `referenceMaterials[{filename, text≤30000}]` 로 프롬프트에 붙임.
- 필기량: 1~5 슬라이더 = **블록당 주석 개수만** 조절 (핵심만 0~1개 … 촘촘 5~7개).
- 구조는 `contentSummary.structure[]` 텍스트 목록뿐. 구조도(스키마) 없음.
- 결제 전에는 미리보기가 비어 있음, 작업은 최근 3건만 보관.

### 개선 설계
**(1) 첨부자료에 역할을 붙이고 지문에 정렬**

| 역할 | 예 | 가중치 |
|---|---|---|
| 학교 프린트 | 담당 선생님 프린트 | 1.0 (시험 직결) |
| 교사용 교과서 | 상문 문학 교사용 교과서 (지금 열려 있는 이육사 「광야」 PDF 같은 자료) | 0.9 |
| 자습서·평가문제집 | | 0.8 |
| 기출 문항 | 학교 기출, 모의고사 | 0.9 (출제 포인트용) |
| 수업 필기 사진 | 학생·교사 필기 촬영본 | 0.7 |
| AI 생성 | | 0.6 |

- 첨부자료 → OCR(5번 파이프라인 재사용) → 세그먼트 → **지문 문장과 정렬** (임베딩 유사도 + 3-gram 겹침).
- 정렬된 곳마다 "이 문장에 첨부자료가 무엇을 적었는지"를 주석 후보로 추출, 출처 표시.
- 두 자료가 다르게 설명하면 **충돌 표시** (예: 화자의 태도 해석이 다름) → 교사가 선택.

**(2) 필기량 = 개수가 아니라 "예산 배분"**
- 페이지 용량 계산: 용지(A4/B4), 단 수, 글꼴 크기, 행간 → 지문 1쪽당 넣을 수 있는 주석 줄 수.
- 우선순위 점수 = 출처 가중치 × 0.4 + 기출 빈도 × 0.3 + 난도(오답률) × 0.2 + 교사 고정 × 0.1
- 필기량 단계는 개수와 함께 **카테고리 구성**을 바꿈:

| 단계 | 들어가는 주석 |
|---|---|
| 1 핵심만 | 출제 포인트, 기출 연계 |
| 2 간결 | + 핵심 어휘, 주제 |
| 3 보통 | + 표현법, 화자·정서 |
| 4 풍부 | + 현대어 풀이 전체, 배경 |
| 5 촘촘 | + 문법, 보충 개념, 첨부자료 전부 |

- 생성 전에 **"예상 2.4쪽"** 표시, 쪽수를 목표로 넣으면 단계를 자동 조정.
- 블록마다 고정 / 숨김 가능. 고정한 것은 필기량을 내려도 남음.

**(3) 스키마(구조도)를 실제 다이어그램으로**
- 갈래별 템플릿을 정해 그래프 JSON(`nodes`, `edges`, 각 노드는 지문 세그먼트 ID에 연결)으로 생성 → SVG로 렌더, 드래그로 편집.

| 갈래 | 스키마 종류 |
|---|---|
| 현대시·고전시가 | 시상 전개도(기승전결/선경후정/시공간 이동), 화자-대상-정서 흐름 |
| 소설 | 인물 관계도, 사건 흐름(발단~결말), 공간 이동 |
| 비문학 | 문단 구조도(주장-근거, 개념-예시, 비교-대조), 개념 관계도 |
| 문법 | 비교 표, 분류 트리 |

- 노드를 누르면 원문 해당 부분이 강조되어 교재 안에서 "구조도 ↔ 원문" 연결이 보임.

**(4) 저작권 안전장치**
- 첨부자료(교사용 교과서 등)는 계정 비공개 저장, 공유 불가.
- 첨부자료에서 온 주석은 **원문 그대로 옮기지 않게** 8-gram 겹침 검사, 기준 초과 시 다시 풀어 씀.

**(5) 기타**
- 첫 블록 무료 미리보기 → 확인 후 전체 생성.
- 작업 보관 무제한, 블록 단위 재생성.

## 3 + 6. 시험지 제작: 변형문제 연속 출제 원리 분석과 개선 (기출변형 검토형 통합)

### 지금 원리 (클라이언트 코드 근거)
- 작업 = **지문 × 유형 × 회차(1~20)** 를 하나의 서버 큐에 넣고 순서대로 처리 (`startVariantSetGenerationContent`, `items[]`, `repeatCount`).
- 지문 자동 배정: 지문을 갈래(POETRY/NOVEL/NONFICTION …)로 분류해 그 갈래의 "99_독립_밑줄_고난도수능형"에 연결.
- box 연속 출제: 브라우저가 박스마다 `지문 × 회차` 작업을 만들어 **하나씩** 보내고 폴링 (localStorage 저장, 탭 닫으면 중단).
- 회차마다 **독립 호출**이고 `round` 번호만 전달. **이전 회차 문항을 넘기지 않음.**
- 클라이언트 코드에서 유사도·중복·임베딩·셔플 로직 없음. 정답 위치도 모델에 맡김.
- 학교급·난이도가 `HIGH / HIGHEST` 로 고정.
- AI 검토는 실행당 1번 묶음 검토(+1연필), 객관식·OX·빈칸 계열만.
- 기출 변형 검토형: 변형 정도 `degree 0/50/100` (선지 변형 / 보기·선지 변형 / 문항 재구성), 문항별 후보 비교·교체·유지, 검사는 **구조 규칙뿐** (선지 수, 정답 범위, 중복 선지, 빈 해설).
- 결과: 같은 지문으로 여러 회차를 뽑으면 **같은 문장을 근거로 한 비슷한 문항이 반복**될 수 있고, 정답 번호가 쏠려도 막는 장치가 없음.

### 개선 설계: "설계도 먼저, 생성은 슬롯별, 유사도는 두 축으로"

**(1) 한 화면 5단계**

```
① 소재  →  ② 설계도  →  ③ 생성  →  ④ 검토  →  ⑤ 출력
지문/기출     무료·즉시     서버 큐      후보 비교     HWPX/PDF
```
- 소재가 **지문**이면 지문 변형, **기출 문항**(OCR 또는 시험지 분석 결과)이면 기출 변형. 기존 "기출 변형" 메뉴와 "검토형"은 여기 ①과 ④로 흡수.
- 약술형도 같은 화면의 출제 유형 하나로.
- box 연속 출제는 "소재 묶음"으로 서버에 저장.

**(2) 설계도(Blueprint) 슬롯**
- 생성 전에 회차별 문항 칸을 먼저 정함. 각 칸:
  - 근거 범위(지문 세그먼트), 발문 유형, 판단축(무엇을 판단하게 하는가), 함정 유형, 난도, **목표 정답 번호**, 원본 기출 문항(있으면)
- 배치 규칙:
  - 지문 문단을 회차 전체에서 고르게 덮음 (같은 문단을 근거로 한 문항은 회차당 1개).
  - 정답 번호 1~5가 회차마다 고르게 (회차 n문항이면 번호별 n/5 ± 1, 같은 번호 3연속 금지).
  - 난도 곡선: 쉬움→어려움 또는 시험지 분석 결과의 분포 그대로.
- 설계도는 표로 보여주고 교사가 칸을 고칠 수 있음 (무료).

**(3) 유사도: 구조 유사도와 표현 유사도 두 축**

| 축 | 계산 | 의미 |
|---|---|---|
| 구조 유사도 S구조 | 0.4 × 같은 발문 유형 + 0.3 × 발문 뼈대 임베딩 코사인 + 0.3 × 근거 세그먼트 Jaccard | "같은 걸 묻는가" |
| 표현 유사도 S표현 | max(본문 임베딩 코사인, 선지 3-gram MinHash Jaccard) | "같은 말로 묻는가" |

- 발문 뼈대: 내용어를 슬롯으로 바꾼 문장. 예) "윗글의 [대상]에 대한 이해로 적절하지 않은 것은?"
- 모드별 목표 (원본 기출 대비):

| 모드 | 구조 | 표현 | 기존 degree |
|---|---|---|---|
| 동형 | 0.7 이상 | 0.35 이하 | (시험지 분석 동형) |
| 선지 변형 | 0.8 이상 | 0.6 이하 | 0 |
| 보기·선지 변형 | 0.6~0.85 | 0.45 이하 | 50 |
| 재구성 | 0.4~0.7 | 0.3 이하 | 100 |
| 신규 | 0.5 이하 | 0.3 이하 | |

- **회차 간 / 문항 간 중복 방지**: 같은 세트 안 어떤 두 문항도 S표현 0.6 이하, 근거 Jaccard 0.5 이하.
- **과거 문항 대비**: 같은 지문으로 예전에 만든 문항(문항 은행, pgvector 검색)과도 비교 → 지난주 시험지와 겹치지 않음.
- **피드백 루프**: 회차 r을 만들 때 앞 회차들의 `(발문 뼈대, 근거 세그먼트, 정답 진술)` 요약을 "이미 사용됨" 목록으로 프롬프트에 넣음 → 사후 검사에서 걸리면 그 칸만 재생성 (최대 2회).

**(4) 자동 검증 (검토형의 구조 검사 + 내용 검사)**
- 구조: 선지 5개, 정답 범위, 중복 선지, 빈 해설, 표 누락 (기존 검사 유지).
- 내용:
  - **풀이 검증**: 다른 모델이 정답 없이 풀어 봄 → 정답 불일치 또는 정답 후보 2개 이상이면 수정.
  - **근거 인용 대조**: 해설의 인용문이 지문에 실제로 있는지.
  - **정답 길이 편향**: 정답 선지가 계속 가장 긴지.
  - **원문 잔존**(기출 변형): 원본 선지가 목표보다 많이 남았는지.
- 검증은 문항 단위라 객관식 외(서술형, 빈칸)에도 적용.

**(5) 검토 화면 (기출변형 검토형 흡수)**
- 문항 카드마다: 이전 후보 / 새 후보 비교, 배지 "구조 72% · 표현 21% · 가장 비슷한 문항 보기", 검증 결과, [이 문항으로 교체] [이전 유지] [직접 수정] [이 칸만 재생성].
- 직접 수정·교체는 무료, 재생성만 해당 칸 비용.
- 자동 모드는 검증을 모두 통과하면 자동 확정, 아니면 그 문항만 검토 대기.

**(6) 비용**
- 견적은 슬롯 수 기준으로 미리 보여주고, 검증 실패로 버린 후보는 차감하지 않음.

## 5 + 7. 시험지 분석·저장 (OCR 통합, 이미지 업로드 추가)

### 지금 확인된 방식
- **시험지 분석**: `.hwp .hwpx .pdf .txt` 만, 20MB. **이미지 불가.** 스캔 PDF는 내부 OCR 작업을 돌린 뒤 분석 → 학부모용 A4 리포트 + 동형 출제용 유형 정보 저장.
- **OCR 탭**: 파일 1개씩, 엔진 3개 선택 (OCR_1 = Gemini, OCR_2 = Qwen `qwen3.7-plus`, OCR_3 = Qwen flash). 결과는 **미리보기 없이 HWPX**, 최근 1건만 30일 보관.
- **강화 OCR**: 9단계(OCR만 ~ 2중 판독 대조), 표·그림 캡처 보존, 30쪽 제한.
- 엔진 모두 **LLM 비전 모델이 글자를 다시 써 내는 방식**. 전용 OCR 엔진(CLOVA, Upstage, Document AI 등)은 코드에 없음.
- 저작권 차단 대응: "자동: OCR_1 2회 후 OCR_2" — **모델만 바꿈**.

### 더 나은 방법 제안
**(1) 입력별 경로 분리 (가장 큰 비용·정확도 개선)**

| 입력 | 처리 | 비용 |
|---|---|---|
| HWP / HWPX / TXT | 직접 파싱 | 0 |
| 글자 레이어가 있는 PDF (한글에서 저장한 PDF 등) | PDF 텍스트 레이어 추출 + 좌표 | 0 |
| 스캔 PDF / 사진 | OCR | 쪽당 |

지금은 PDF면 무조건 OCR 비용이 붙는데, 학교 시험지 PDF 상당수는 글자 레이어가 있어 OCR이 필요 없음.

**(2) 2단 구조: 글자 인식은 전용 OCR, 구조화는 LLM "참조형"**
- 1단: 한국어에 강한 전용 문서 OCR(Upstage Document Parse 또는 NAVER CLOVA OCR 등)로 **줄 단위 텍스트 + 좌표 + 신뢰도**.
- 2단: LLM에는 줄 목록(`L001 …`)과 페이지 이미지를 주고, **글자를 다시 쓰지 말고 줄 번호로만 구조를 답하게** 함.
  - 예) `{문항: 12, 발문: [L040-L041], 보기: [L042-L048], 선지: {1:[L049], …}}`
- 효과:
  - LLM이 긴 원문을 그대로 출력하지 않으므로 **저작권(인용 반복) 차단이 거의 발생하지 않음**.
  - 출력 토큰이 크게 줄어 비용이 내려감.
  - 글자를 LLM이 "고쳐 쓰는" 환각(맞춤법 자동 수정, 누락)이 사라짐.
- 엔진 선택은 실제 학교 시험지 20쪽으로 글자 오류율(CER)을 재서 정함 (PoC 1주).

**(3) 신뢰도 기반 재판독**
- 신뢰도 낮은 줄만 잘라 확대해 두 번째 엔진으로 다시 읽고, 두 결과가 다르면 노란색 표시.
- 지금의 "2중 판독 대조(4연필)"를 문서 전체가 아니라 **문제 되는 줄만** 적용.

**(4) 나란히 보기 교정 화면**
- 왼쪽 원본 이미지, 오른쪽 텍스트. 줄을 클릭하면 이미지 위치가 강조.
- 키보드만으로 다음 의심 줄 이동(`Tab`), 수정, 확정.
- 교정한 결과는 지문·문항 데이터로 저장 → 주석 달기, 시험지 제작에서 바로 사용.

**(5) 이미지 업로드 추가**
- 형식: PNG, JPG, WebP, **HEIC**(아이폰), 여러 장 한 번에.
- 넣는 방법: 드래그, 파일 선택, **클립보드 붙여넣기(Ctrl+V)**, 모바일 **카메라 바로 촬영**.
- 자동 전처리: 기울기 보정, 원근 보정(사진 찍은 시험지), 그림자·배경 제거, 회전 감지, B4 양면 펼침을 2쪽으로 분할, 2단 편집 인식.
- 쪽 순서 드래그 정렬, 쪽 삭제·교체.
- 한도: 한 작업 100쪽 (지금 30쪽).

### 7. OCR 탭 통합과 저작권 차단 시 자동 대체
**하나의 화면, 세 가지 모드**

| 모드 | 하는 일 | 대체되는 기존 메뉴 |
|---|---|---|
| 텍스트화 | 글자만 뽑아 HWPX/TXT | OCR 탭 |
| 구조화 | 문항·보기·선지·표·그림 분리, 해설 보완 선택 | 강화 OCR |
| 분석 | 구조화 + 출제 경향 리포트 + 동형 설계도 저장 | 시험지 분석 |

세 모드 모두 같은 OCR 결과를 공유하므로, 텍스트화했던 시험지를 나중에 분석으로 올려도 **OCR 비용을 다시 내지 않음**.

**저작권 차단 시 대체 순서 (쪽 단위로 적용)**

```
1. 기본 엔진 (예: Gemini 구조화)
     ↓ 차단 감지
2. 참조형 구조화: 전용 OCR 줄 목록 + LLM은 줄 번호만 출력
     ↓ 실패
3. 대체 비전 모델 (예: Qwen-VL)
     ↓ 실패
4. 타일 모드: 쪽을 단·문단 단위로 잘라 따로 처리 (짧은 출력)
     ↓ 실패
5. 전용 OCR 텍스트 + 규칙 기반 구조화 (문항번호 "1.", 선지 ①~⑤, [보기] 패턴)
     ↓ 실패
6. "수동 확인 필요" 표시 (그 쪽만)
```

- 차단 감지 기준: 응답 종료 사유가 인용 반복(RECITATION)·안전(SAFETY)·금지 콘텐츠, 빈 응답, 또는 **출력 글자 수가 예상의 50% 미만** (잘림을 차단으로 간주).
- 쪽마다 어떤 엔진으로 끝났는지 기록: "3쪽: 기본 엔진 차단 → 참조형으로 완료".
- 성공한 단계만 과금, 실패 단계는 차감하지 않음.
- 이 대체는 교사가 보유한 시험지·교재를 수업용으로 디지털화하는 용도. 결과는 계정 비공개이며 공유 기능을 두지 않음.

**분석 결과 품질 관리**
- 문항 신뢰도 0.65 미만은 지금처럼 "검수 필요"로만 두지 않고, **교사가 확인하기 전에는 동형 설계도에 쓰이지 않게** 막음.

## 8. 시험지 디자인 작업대 고도화

### 지금
- 3단 화면(설정 / 미리보기 / 쪽 썸네일), 프리셋 저장(계정), HWPX 7틀·PDF 10틀·표지 4종.
- 미리보기는 **고정 샘플** (내 문항이 아님).
- 머리 띠(배너)는 틀마다 **고정 색**. 이미지로 바꿀 수 없음. 올릴 수 있는 건 로고(PNG 1MB)와 표지뿐.
- 프롬프트 자체 HTML 디자인이 프리셋을 덮어쓸 수 있음. HWPX는 가로 방향 잠김.
- 교재디자인은 별도 화면이고 작업이 브라우저에만 저장.

### 개선 설계
**(1) 내 문서로 미리보기**
- 자료함의 최근 결과나 지금 만든 시험지를 그대로 불러와 미리보기. 샘플은 결과가 없을 때만.

**(2) 슬롯 방식 이미지 배너 (자유 교체)**
- 모든 틀을 슬롯으로 정의: `표지`, `머리 배너`, `구역 구분 띠`, `꼬리말`, `워터마크`, `로고`.
- 슬롯마다 모드 선택: **자동(틀 색) / 이미지 업로드 / 내 라이브러리 / 글자만 / 없음**.
- 이미지 설정: 맞춤(채우기/맞추기), 초점 위치(드래그), 높이(mm), 투명도, 적용 쪽(모든 쪽 / 첫 쪽만 / 홀수 / 짝수).
- **미리보기 위 배너를 클릭하면 바로 교체 패널**, 이미지 파일을 배너에 끌어다 놓으면 즉시 교체.
- 배너 위 글자색은 배경 밝기를 계산해 자동(흰/검) 선택, 대비 부족 시 경고.
- 업로드한 로고·배너에서 색을 추출해 강조색 3개 추천.
- 형식: PNG, JPG, WebP, SVG / 배너 5MB, 권장 비율 안내 (A4 머리 배너 약 180×25mm).

**(3) 레이아웃 자동 점검**
- 문항이 단·쪽 사이에서 잘리면 경고하고 "다음 단으로 넘기기" 자동 적용 (발문·보기·선지 묶음 유지).
- 목표 쪽수 입력 → 글자 크기·행간·여백을 허용 범위 안에서 자동 맞춤.
- 지문과 문항이 다른 쪽으로 떨어지면 표시.

**(4) 작업 흐름**
- 실행 취소/다시 실행, 변경 전후 비교, 프리셋 버전 기록.
- 단축키: `Ctrl+Z`, `Ctrl+S` 저장, `[` `]` 쪽 이동, `+` `-` 확대.
- "B4 2단 시험지 → A4 학습지" 같은 변환 한 번에.
- HWPX 가로 방향 허용(용지 방향은 HWPX에서도 설정 가능), 단 일부 틀은 세로 권장 안내.
- 프롬프트 HTML은 프리셋을 덮어쓰지 못하게 하고, 데이터와 디자인을 항상 분리.
- 교재디자인의 페이지 편집기를 "페이지 편집 모드"로 합치고 작업을 서버에 저장.

## 9. 가맹 전용 없애고 에이전트 친화적으로

### 원칙
- 메뉴에서 가맹 구역과 잠금 아이콘을 없애고 **모든 기능을 같은 자리**에 둠. 과금은 연필(사용량)로만.
- 모든 기능은 **화면 = API = 에이전트 도구** 로 같은 계약을 씀.

### 에이전트 친화 설계
| 항목 | 설계 |
|---|---|
| 단일 작업 API | `POST /v1/jobs` (kind: ocr, analyze, annotate, textbook, build, render), `GET /v1/jobs/{id}`, `GET /v1/jobs/{id}/events` (SSE) |
| 견적 | `POST /v1/jobs?dry_run=true` → 예상 연필, 쪽 수, 소요 시간. 실행 없음 |
| 멱등성 | `Idempotency-Key` 헤더. 같은 키로 다시 보내면 같은 작업 반환 (중복 차감 없음) |
| 오류 | `{code, message, retryable, retry_after}` 고정 형식. 예: `OCR_BLOCKED_ALL_ENGINES`, `INSUFFICIENT_PENCILS` |
| MCP 서버 | 도구: `quote`, `ocr_document`, `analyze_exam`, `annotate_passage`, `build_textbook`, `build_exam`, `render_document`, `get_job`, `list_assets`, `upload_asset` |
| API 키 | 범위(scope)와 **키별 월 연필 한도**, 사용 기록, 즉시 폐기 |
| 웹훅 | 작업 완료·실패 시 호출, 서명 포함 |
| 문서 | OpenAPI 명세, `/llms.txt` 에 기능·계약 요약 |
| 화면 쪽 | 모든 화면 상태를 URL에 담음(localStorage 의존 제거), 버튼·입력에 안정적인 이름(aria-label) |

### 작업 요청창 (Ctrl+K)
- 자연어로 요청: "이 PDF OCR해서 1~3번 지문 행간주 B4로, 필기량 3"
- 에이전트가 단계 계획과 견적을 보여줌 → [실행] 한 번으로 큐에 등록.
- 같은 요청을 루틴으로 저장해 반복 실행(예: 매주 학교 프린트 → 주석교재).

- 삭제: 대시보드, 출결 관리, 학생 관리, 질문방, 시험 관리, 모의고사 관리, 성적 조회, 메시지 발송(Solapi 연동 포함).
- "저장된 시험지"는 **자료함**으로 이동 (학생 배포 기능 없이 보관·재출력만).
- DB에서 학생·학부모·반·응시·응답 테이블과 학생 분석 뷰 제거 (`kor_core.sql` 수정 완료).
- 유지: 전국 오답률 데이터와 `v_national_priority` (시험지 제작 설계도의 난도·우선순위 근거로 사용).

## 11. 설정 디자인 전문화

### 지금
- 크림·초록 둥근 카드, 카드마다 저장 버튼(빠른 정답 저장, 프롬프트 제목 저장, 기본 틀 저장 …), 주석교재 디자인은 썸네일만 있고 실시간 미리보기 없음, 섹션 3개가 한 페이지에 길게 이어짐.

### 개선 설계
**레이아웃**
- 왼쪽 고정 내비 + 가운데 설정 + (디자인 관련 항목일 때만) 오른쪽 실시간 미리보기.
- 섹션: 계정 · 학원 브랜드 · 출력 기본값 · 주석교재 기본값 · 디자인 프리셋 · 연필·사용내역 · API·에이전트 · 알림 · 보안.
- 사용내역(지금 별도 메뉴)을 "연필·사용내역"으로 흡수.

**행동**
- 카드별 저장 버튼 제거 → 하단 고정 바 하나: "변경 3개 · [되돌리기] [저장]". 저장 안 하고 나가면 확인.
- 설정 검색(`/`), 항목마다 "기본값으로" 링크, 변경 이력(누가 언제).
- 위험 작업(키 폐기, 계정 삭제)은 별도 "위험 구역"으로 분리.

**시각 규칙**
- 중립 회색 바탕 + 강조색 1개(브랜드색). 카드 배경색 구분 대신 얇은 구분선과 여백.
- 8px 격자, 행 구조 = 왼쪽 라벨·설명 / 오른쪽 컨트롤.
- 글자 위계: 섹션 제목 20px/600, 항목 14px/500, 설명 12px 회색. 숫자는 고정폭.
- 버튼 모양 통일(주 버튼 1개만 채움), 둥근 알약 버튼 남용 제거.
- 다크 모드 동일 품질 지원.
